# Handoff: hardening, the remote CLI, and two tagged releases

Written 2026-08-22, overnight, on `main`. Everything below is pushed, CI is
green, and 753 tests pass.

## What shipped

**v0.1.0-alpha.1** and **v0.1.0-alpha.2** are tagged. Before this the whole
repo was `0.0.0`, which gave `hobby update` nothing to compare against.

### Studio hardening

There were no security headers anywhere, not even on the static bundle. Every
response from that listener now carries a content security policy with
`script-src 'self'` and no inline exemption, `frame-ancestors 'none'`, nosniff,
no-referrer, and a permissions policy. Applied at `createStudioApp` before any
handler runs, so there is one place to get it right. HSTS is sent only over
real TLS, because sending it on `http://127.0.0.1` would pin loopback to https
for a whole browser profile.

Sessions had no expiry: the store's own comment said a session lived until the
daemon restarted, so on a box that stays up a stolen cookie stayed valid
forever. They now die on a 12 hour idle clock or a 30 day absolute one,
whichever trips first. The absolute clock is never refreshed, which is what
stops an attacker holding a token open by using it.

### The proxy no longer puts Postgres on the internet

ADR 0017. `proxyHost` defaults to `127.0.0.1` and takes an address, `"tailnet"`
(loopback plus this machine's Tailscale address) or `"all"`. **Breaking** for
anyone relying on the old bind.

Verified on a box: public port closed, tailnet wake working from a Mac.

### The CLI talks to a remote box

ADR 0018. `hobby login`, `logout`, `remote ls`, `link`, `token create/ls/rm`.
`createApi` takes a transport rather than a socket path, so every existing verb
works remotely without knowing it.

Verified end to end: a project created on a box from a Mac over a tailnet, woken
and slept remotely, `hobby link` writing `hobby.json`, and `hobby create` then
working with no `--project` flag.

### The Linux queue producer path

Both halves, per the finding filed the same day. Containers now map
`host.docker.internal`, and the daemon binds a project's bridge gateway when
that project is created rather than only at daemon startup. Verified live: a
project created while the daemon ran added `172.19.0.1:7434` immediately.

### Also

`hobby update`, a systemd unit so the daemon outlives an ssh session, and
`bun.lock` gitignored.

## What is still open

**The proxy still has no TLS.** ADR 0017 bought safety by binding loopback, not
by encrypting anything. `"all"` remains a loaded gun and its documentation says
so. Real TLS on the proxy is the larger piece nobody has started.

**Tokens have no scopes and no expiry.** Deliberate, per ADR 0018, but it means
a leaked token is full access until revoked by name.

**Snapshots are still unreachable.** Unchanged. `takeSnapshot` has only test
callers, and `pg_dump` is still the backup story.

**An intermittent test failure.** The suite reported `fail 1` twice across
roughly ten runs and would not reproduce; every targeted rerun passed and the
final state is 753 passing. Something in there is timing-sensitive and worth
finding before it is trusted as a gate.

**vm-01 needs Tailscale SSH re-auth.** It asked for an interactive login
partway through the night, which is not something to do on someone's behalf, so
the second half of the work was verified on vm-02 only. vm-01 is still on
alpha.1.

## Traps worth knowing

**`pkill -f "hobby.js daemon"` over ssh kills your own session**, because the
pattern matches the ssh command string. Cost real time. Use a pattern that
cannot match itself.

**A backgrounded daemon holds the ssh channel open** even with `nohup` and
`setsid`. That is what the systemd unit is for; use it rather than fighting it.

**The 1GB box has no swap**, so a build pins its single CPU at load 8 and
tailnet ssh times out during it. The box is fine; wait, or use the public
address.

**alpha.1 cannot `hobby update` to alpha.2.** Its updater counted untracked
files and `bun install` always leaves one. Re-run the install one-liner once.
Documented on the CLI reference page.
